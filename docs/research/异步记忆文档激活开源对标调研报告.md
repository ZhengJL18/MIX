## 一、DSH / DeepSeek Harness 生态

### 1.1 官方机制：AGENTS.md 注入 = 纯静态分层注入（无检索、无异步激活）

- 仓库：https://github.com/deepseek-ai/deepseek-harness （112,963★，2026-08-15 仍活跃；标语 "Everything is a Plugin"）
- **注入机制源码核实**（本机 `@deepseek-ai/dsh-agent-instructions` 包 lib/index.js）：
  - 注入时机 `ctx.on("agent/pre-step", ...)`——**每一步（step）之前同步注入**，非异步
  - 注入内容：`$DSH_HOME/AGENTS.md`（user-global）+ 项目根到 cwd 全部祖先目录的 AGENTS.md/CLAUDE.md/AGENTS.local.md/CLAUDE.local.md，**全量加载**（非按相关性筛选），受 maxBytes 字节预算限制、超预算截断
  - 优化仅有：versionCache 按 scope 记录 SHA-1 版本跳过未变文件重读；touchedPaths 机制（工具改动某路径文件后把该目录指令投影进来）
  - **源码 grep search/retriev/fuzzy/embed/vector/relevan 零命中** → 确认纯静态注入
- 官方唯一"检索"能力：`ctx.sessionQuery`（[dsh-session-query-sqlite](https://github.com/deepseek-ai/deepseek-harness/tree/master/packages)，SQLite FTS 会话历史检索，供插件/工具调用）+ compaction（上下文压缩/蒸馏）。均非"记忆文档检索激活"。官方 README 无任何 memory/记忆概念。
- 插件体系：cordis 插件框架，`dsh plugin --profile web add <pkg>` 安装；官方脚手架 [create-dsh-plugin](https://www.npmjs.com/package/create-dsh-plugin)（2026-08-13）；社区插件清单 [awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)（Memory 分类 **30+ 个记忆插件**）。

### 1.3 对 Flutter 纯 Dart 手机端复刻的可借鉴性

1. **循环钩子范式**：DSH 插件用 `agent/pre-step`、`agent/turn-stopping`、`tools/result`、`session/event` 挂记忆逻辑——Flutter 复刻的对话循环应定义等价钩子（步骤前检索注入 / 回合末异步写入 / 工具执行后记录）。
2. **检索实现选项**：词法 BM25/关键词（Noema——无向量、可解释，最贴近"热词匹配"诉求）；SQLite FTS5（手机端现成，Dart 侧 `sqlite3_flutter_libs` 内置 FTS5）；混合检索（关键词+向量+rerank，手机端成本偏高）。
3. **异步模式**：独立后台进程（noema-mcp Rust / PowerContext Python）手机端不适合多进程，但"超时跳过、不可用即降级"的思路可移植；同进程后台循环（autoDream / auto-memory 每回合子代理沉淀）用 Dart Isolate / async task 即可。
4. **Markdown 载体**：社区普遍 Markdown + frontmatter，与"记忆文档"诉求一致；写入策略有确认制（AI 提议、用户采纳）与自动沉淀（dsh-auto-memory 每回合自动写+去重+蒸馏）两种成熟做法。
5. **结论**：**没有任何 DSH 插件把"异步检索+注入激活"做成完整闭环**——最接近的是 powercontext-dsh（自动但同步带超时）与 dsh-auto-memory（异步写入但静态注入）。"对话开始时按相关性异步唤醒记忆文档"在 DSH 生态同样是半成品。

## 三、学术/架构参照：Letta sleep-time compute × Hermes memory_manager

### 3.1 Letta 的 sleep-time compute

- **论文**：https://arxiv.org/abs/2504.13171 *Sleep-time Compute: Beyond Inference Scaling at Test-time*（Lin/Snell/Wang/Packer/Wooders/Stoica/Gonzalez）。⚠️ **attribution 澄清**：该论文不是 Letta 独有出品（是 Sky Computing/Berkeley 主导、Letta 团队参与），Letta 把它引入产品并写进官方博客 https://www.letta.com/blog/sleep-time-compute 。
- **论文层面**：sleep-time compute = 在用户提问前的空闲期"离线思考上下文、预计算可能被问到的量"，把算力从高延迟 test-time 搬到空闲期——**主题是离线预推理，不是记忆检索**。
- **产品实现**（源码核实 [letta-ai/letta](https://github.com/letta-ai/letta)）：
  - 触发：**每 N 轮对话后**（`sleeptime_agent_frequency`，[group_manager.py](https://github.com/letta-ai/letta/blob/main/letta/services/group_manager.py)），非空闲定时器
  - 异步程度：**同进程内 asyncio 后台任务**（`safe_create_task` 派到同一事件循环，前台立即返回），非独立进程/消息队列
  - 做什么：后台重放对话→独立 sleeptime agent 用 memory 工具整理记忆块（"background agent that asynchronously processes conversations... memory management"）
  - **记忆载体已演进为 MemFS = git 托管的 Markdown 文件**（[MemFS 文档](https://docs.letta.com/concepts/memfs)）：`system/` 下文件每轮自动进 system prompt，`reference/` 默认不进上下文、靠文件树当路标由 agent 主动读；**默认无语义/向量索引**（关键词搜索需可选 mod）→ 记忆文档分层思想可借鉴
  - **无"系统自动按相关性唤醒文档注入"**——自动进上下文的只有 system/ 全量文件，文档激活是 agent 主动调工具
- **可借鉴性**：双 agent 分权（主 agent 不持记忆编辑工具、后台 agent 专管记忆）→ Dart 用后台 Isolate 跑轻量整理；频率门控（每 N 轮）纯计数器即可；MemFS"常驻层 vs 按需层"分层可直接移植到 Markdown 记忆。不可搬：语义检索依赖 embedding 服务/向量库；sleep-time 需要第二个能调 LLM 的 agent（手机端成本受限）。

### 3.2 Hermes（NousResearch/hermes-agent）的 memory_manager —— "异步激活"最完整工程范式

- **仓库**：https://github.com/NousResearch/hermes-agent ；官方文档 https://hermes-agent.nousresearch.com/docs/user-guide/features/memory 、memory-providers
- **前提纠正**：`MemoryManager` 只在配置了外部 memory provider 时才创建（[agent_init.py](https://github.com/NousResearch/hermes-agent/blob/main/agent/agent_init.py)）；**内置记忆 MEMORY.md/USER.md 是"冻结快照"——会话开始时加载一次注入 system prompt、中途不更新**，不经过 prefetch/sync。prefetch/sync 是外部记忆后端（Hindsight/Mem0/Honcho）的编排层。
- **prefetch_all（回合前异步唤醒注入）**：每轮 tool loop 前调用（受 trivial-prompt 门控过滤 "hi/thanks/ok"），结果包成 `<memory-context>` 围栏 + "recalled memory context, NOT new user input" 注记注入该轮用户消息（[turn_context.py](https://github.com/NousResearch/hermes-agent/blob/main/agent/turn_context.py)）。异步程度：外部 prefetch 在 daemon 线程跑，但主线程 `thread.join(8.0s)` **有界阻塞最多 8 秒**、超时跳过本轮（[memory_manager.py](https://github.com/NousResearch/hermes-agent/blob/main/agent/memory_manager.py)）——不是纯 fire-and-forget。
- **queue_prefetch_all（为下一轮预热）**：回合结束后后台跑 `queue_prefetch` 为下一轮准备召回（[run_agent.py](https://github.com/NousResearch/hermes-agent/blob/main/run_agent.py)）；Hindsight 实现用 daemon 线程缓存结果，下一轮 prefetch 默认只读缓存。
- **sync_all（回合后异步写记忆）**：**不在回合主路径内联执行**，派给单 worker 的 daemon ThreadPoolExecutor（`DaemonThreadPoolExecutor(max_workers=1)`）——docstring 记录真实事故：某 provider 内联 sync 阻塞 ~298s 卡死 agent；单 worker 保证第 N 轮写入先于第 N+1 轮；配套 `flush_pending()` / `shutdown_all()`（5s 有界排空）。有专门回归测试 [test_memory_async_sync.py](https://github.com/NousResearch/hermes-agent/blob/main/tests/agent/test_memory_async_sync.py)（"end-of-turn memory sync must not block the turn"）。
- **热词匹配**：内置 memory 工具 replace/remove 用**唯一子串匹配**（编辑定位，非检索）；外部 provider（Hindsight）检索为 "semantic search, keyword matching, entity graph traversal, and reranking"；另有 FTS5 会话搜索+LLM 摘要（官方文档）。
- **结论**：**是真异步后台线程，不是启动时一次性预取**——回合后写 + 下一轮预热均走后台线程，有超时、排空、daemon 兜底。
- **可借鉴性**：委托方诉求 (a) 最直接的工程范式就在这里：回合前 prefetch（后台检索+主线程有界等待+超时降级跳过）+ 围栏注入（`<memory-context>` + "非用户输入"注记）+ 回合后 sync（单 worker 串行保序）+ queue_prefetch 预热下一轮 + trivial-prompt 门控。Dart 对应物：Isolate/串行队列做后台写、`Future.timeout` 做有界等待、fenced 注入直接拼进 prompt。

## 总结：'异步记忆文档激活'在开源世界的成熟度

**结论：这个组合没有生产级的一体化插件，但每个组件都有成熟参照，且"异步"与"激活"已有可抄的工程范式——它是"拼装态"，不是"论文态"，也不是"无人做过"。**

分维度看：

1. **异步写入（记忆自动沉淀）**：已有多处生产级实现——Hermes sync_all（单 worker 后台保序写）、PMB（先落 SQLite、后台线程算向量，MCP 返回 <1ms）、OpenClaw dreaming（后台蒸馏）、dsh-auto-memory（每回合子代理自动沉淀）、Letta sleeptime（同进程 asyncio 后台整理）。**这一半成熟**。

2. **检索激活（把相关记忆文档唤醒注入）**：**没有任何项目做到"对话开始时/进行中异步检索相关文档→非阻塞注入"的完整闭环**。现状分两类：
   - *同步激活*：Hermes prefetch_all（后台线程检索但主线程有界 join 8s）、powercontext-dsh（pre-step 自动 recall+超时跳过）、PMB 每消息 auto-recall（sub-ms 同步）、Basic Memory SessionStart（同步 hook+timeout fail-open）、dsh-memory-director（pre-step 同步检索注入）——**"唤醒注入"都有，但都带同步等待（哪怕有界）**。
   - *异步但非检索*：OpenClaw 会话开始加载今日/昨日笔记（按时间不按相关性）、Hermes queue_prefetch（为下一轮预热，异步但不阻塞当前轮）、DSH AGENTS.md（静态全量注入）。
   - 所以"**完全异步（fire-and-forget）的检索激活**"在开源世界**尚未做成品**；主流做法是"后台检索 + 有界等待 + 超时降级"，Hermes 是其中工程最完整的范式。

3. **Markdown 文档型记忆**：成熟且主流——OpenClaw（USER.md/MEMORY.md/日期笔记）、Hermes 内置（2 文件冻结快照）、Letta MemFS（git 托管 Markdown 文件树）、Noema（Markdown+frontmatter+BM25）、dsh-mneme（SQLite+Markdown 双写）、Basic Memory、memory-bank 方法论。**载体共识已形成**。

4. **热词匹配搜索**：成熟——Noema BM25、context-memory FTS5+stemming、claude-memory-fts/PMB/dsh-mneme/OpenClaw 的混合检索（关键词通道+可选向量）、Hermes 子串匹配。Dart 端可直接用 SQLite FTS5。

**给 Flutter 纯 Dart 复刻的最优拼装路径**：以 **Hermes prefetch/sync 为异步骨架**（回合前 Isolate 检索 + `Future.timeout` 有界等待 + `<memory-context>` 围栏注入；回合后单串行队列异步写）+ **OpenClaw/MemFS 为文档分层**（MEMORY.md + 日期笔记 + system/常驻 vs reference/按需，会话开始加载今日/昨日）+ **Noema BM25 / SQLite FTS5 为热词检索**（纯 Dart 可落地、无向量依赖）。这三块拼起来就是"异步记忆文档激活"，目前开源世界没有单一项目同时做完这三件事。
